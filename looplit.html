Looplit

会議の記録を、実行できる仕事へつなぐ。

Looplitは、AI議事録、会社・チームの予定、担当業務を、会議から実行まで一つの運用フローとしてつなぐWeb workspaceです。

2026Product Design / UX Strategy / DevelopmentNext.js / Supabase / OpenAIWeb

01 / Problem

会議録が残っても、その後の仕事は別の場所で始まる。

会議の内容をまとめた後、予定を登録し、担当者へ依頼し、進捗を追う作業は複数のツールに分かれます。同じ決定をコピーし直すたびに、発言の根拠とチームの文脈が薄れていきます。

01

記録と実行の分断

議事録に残したNext stepが、担当業務へ変わらず止まる。

02

情報の再入力

同じ内容を議事録、カレンダー、タスクへ繰り返し移す。

03

根拠の消失

要約だけが転記されると、判断に使った原文へ戻りにくい。

02 / Connected Operating Flow

機能を並べるのではなく、仕事が進む順序でつなぐ。

録音、整理、予定、担当、フォローアップを一つの流れとして設計。会議で生まれた情報が、確認可能な状態のまま次の行動へ移ります。

→
02Organize要約・決定
→
03Schedule次の予定
→
04Assign担当業務
→
05Follow up進捗確認

03 / Human Review

AIが決めるのではなく、
確認できる候補をつくる。

会議音声を話者つきで文字起こしし、要約、決定事項、Action candidateを構造化します。担当者や期限を推測で確定せず、人が確認した内容だけをチームの業務へ反映します。

  • 要約と決定を全文Transcriptへ接続
  • Next stepは確定前の候補として表示
  • 承認後に担当者、期限、優先度、状態を付与

04 / Product Principles

同じ情報を、何度も運ばなくてよい構造へ。

会議、予定、担当業務を別々の機能として終わらせず、チームとプロジェクトの文脈で接続しました。

Connected

一度記録し、続けて使う

議事録の決定とNext stepを、予定や担当業務へつなげる。

Human Review

提案と確定を分ける

AI出力をそのまま反映せず、人の確認を操作として残す。

Team Context

誰の仕事かを保つ

会議、予定、業務を関係するチームとプロジェクトへ紐づける。

05 / Current Outcome

会議から実行までの主要フローを、動くWeb productとして構築した。

録音、話者つき文字起こし、構造化されたAI結果、Transcript Reference、予定、担当業務を一つのworkspaceに実装しました。公開利用指標はまだなく、現在は情報の接続とHuman Reviewの検証を優先しています。

AI議事録の価値は、要約の完成度だけではなく、決定を確認し、次の仕事へ安全につなげられる構造で決まる。
