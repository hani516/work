Blinq

予定とお金を、同じ時間軸で振り返る。

Blinqは、別々に使われていた家計簿とカレンダーを統合し、支出が発生した日の行動まで一緒に見返せるライフスタイルアプリです。

2025.03 - 2025.08Product Design / UIUX / Visual Design1 Designer / 1 DeveloperMobile

01 / Problem

金額は分かっても、なぜ使ったのかを振り返れない。

家計簿は支出カテゴリを、カレンダーは予定を記録します。しかし旅行、通院、会食のように予定と支出が結びつく場面では、二つのアプリを行き来しなければ文脈を確認できませんでした。

01

支出の背景が見えない

金額とカテゴリだけでは、その支出が発生した日の行動を思い出しにくい。

02

アプリ切り替えの手間

予定と支出を別々に記録するため、確認と入力のたびに移動が発生する。

03

次の支出を予測しにくい

過去の予定と支出が分離されていると、似た予定に必要な金額を見積もりにくい。

02 / Information Model

日付を共通キーにして、予定と収支を一つの画面へ。

カレンダー上部に予定、下部に収支を置き、同じ日付の出来事と金額を同時に確認できる構造にしました。

Calendar model

統合カレンダーに加えて、情報量を調整したいユーザー向けに家計簿のみ、予定のみの表示も用意しました。

Dashboard

必要な文脈だけを、タッチで切り替える。

統合、家計簿、スケジュールの3状態を同じカレンダー基盤で表示。選択した日付の詳細を画面内で確認できるようにしました。

  • 統合: 予定と収支を同時に表示
  • 家計簿: 月の収入・支出と明細を表示
  • スケジュール: 予定のみを表示

03 / UX Iteration

モード切替をTab Barに隠した結果、学習コストが生まれた。

リリース後の行動観察から、ホームボタンを押して3種類のカレンダーを切り替える操作が、一般的なTab Barのメンタルモデルと衝突していることを確認しました。

Before → After

切替式の3タブを、予算、家計簿、ホーム、スケジュール、設定の5つの明示的な目的地へ再整理。オンボーディングに頼らなくても移動先を予測できる構造に変更しました。

04 / Learning

新しい操作を発明するより、学習済みの期待に沿う。

情報を統合するアイデアと、移動方法の分かりやすさは別の問題でした。機能の独自性を保ちながら、ナビゲーションは慣習、アフォーダンス、メンタルモデルを優先しました。

Model

日付で文脈を統合

予定と支出を同じ時間軸で扱い、出来事の背景まで振り返れるようにした。

Observe

リリース後も行動を見る

実際の操作から、説明が必要なナビゲーション構造を改善対象として発見した。

Update

目的地を明示

隠れたモード切替をやめ、各機能を予測可能なTab Barへ配置した。

独自性は情報の組み合わせでつくり、操作方法はユーザーがすでに知っている規則に合わせる。
